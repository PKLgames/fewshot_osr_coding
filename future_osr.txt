════════════════════════════════════════════════════════════════════
二、根因分析: 为什么Flow OSR无法通过loss调参修复
════════════════════════════════════════════════════════════════════

三轮实验的统一证据:
  1. z_consistency mean separation ≈ 0 在所有实验中 (osr18a: -0.01, osr18b: -0.01, osr18c: -0.00)
  2. flow_energy mean separation ≈ 0 或负值 (osr18a: -1.10, osr18b: +0.73, osr18c: -0.53)
  3. 即使osr18b中z_norm²爆炸到78, z_consistency仍然≈0 — 问题不是z空间的值, 而是区分力
  4. flow_hybrid在calibration时TPR=15.65%, 但test只有4.20% — flow信号是噪声, 不是信号

根本原因: **架构限制, 不是参数问题**

  当前flow架构:
    ConditionalNSF(input=32, condition=32, 4 coupling layers, hidden=128)

  问题:
    1. Flow是光滑双射, 对所有condition产生相似的映射
       → z(x|proto_c1) ≈ z(x|proto_c2) for any x
       → condition (prototype) 仅轻微影响映射, 不足以产生类间区分

    2. 条件注入方式太弱: prototype作为附加输入拼接到coupling layer
       → 4层coupling, 每层hidden=128, 条件信号被淹没在变换中
       → 需要10-100x更强的条件机制 (FiLM, cross-attention等)

    3. z_correct和z_wrong通过同一网络变换, 区别仅在于condition不同
       → 如果条件信号弱, z_correct ≈ z_wrong → 无法区分

  这解释了为什么:
    - L_non_gaussian强 (osr18b): 推z_wrong远离N(0,I)的同时推走z_correct → z_norm²爆炸
    - L_non_gaussian弱 (osr18c): z_wrong ≈ z_correct ≈ N(0,I) → 无区分力
    - 无L_non_gaussian (osr18a): 同上, z_wrong ≈ z_correct
    → 无论怎么调, flow都无法区分, 因为架构决定的

  **损失调整无法修复架构缺陷。**


════════════════════════════════════════════════════════════════════
三、决策: 停止flow OSR loss调参方向
════════════════════════════════════════════════════════════════════

已穷尽的搜索空间:
  ✗ 无反归一化力 (osr18a) → flow OSR ≈ 3-5%
  ✗ 强反归一化力 3.2:1 (osr18b) → z爆炸, 分类崩溃
  ✗ 温和反归一化力 0.5:1 (osr18c) → z稳定, flow OSR仍≈3%
  ✗ Phase 1无归一化 → z混乱
  ✗ Phase 1轻归一化 → z稳定但flow仍无区分力
  ✗ energy_margin从小到大 (0→0.15→0.20→0.25) → 无明显效果
  ✗ latent_repel从小到大 (0→0.10→0.40) → 无明显效果或爆炸

结论: **flow OSR loss调参方向已充分验证, 结论是否定的。不再在此方向微调。**


════════════════════════════════════════════════════════════════════
四、当前最优方案: osr18a
════════════════════════════════════════════════════════════════════

  闭集ACC:  68.89%
  最优OSR:  anti_prototype 17.62%

  Flow的作用: **仅用于分类增强**, 不用于OSR
    - Flow density estimation帮助分类 (proto_centered + flow_centered)
    - condition_alpha搜索对分类无影响 (proto_scores主导)
    - gaussian prior让z空间有序, 支持flow稳定训练

五、下一步计划: 两个可选方向
════════════════════════════════════════════════════════════════════

────────────────────────
方向A (推荐): 特征空间OSR增强 — 在osr18a基础上
────────────────────────

  思路: 放弃flow OSR, 专注提升特征空间方法 (anti_proto已17.62%)

  改进点:
    a) 增强OOD暴露:
       - 当前: 4个unknown类 × 1800 = 7200样本
       - 改进: 增加hard negative mining, 用GMM边界样本
       - 预期: anti_proto 17.62% → 20-23%

    b) 改进anti_prototype:
       - 当前: 简单L2距离反转
       - 改进: 加入类内方差加权, adaptive margin
       - 预期: 精度提升2-3%

    c) 改进ood_head:
       - 当前: 5-dim特征 (距离/比率/softmax/entropy/norm)
       - 改进: 加入flow density作为额外特征 (不是OSR信号, 而是辅助信息)
       - 预期: ood_head 10.48% → 12-15%

    d) 集成方法:
       - Top-3方法加权投票: anti_proto + geo_fusion + ood_head
       - 预期: 集成 20-25%

  代码改动: 仅修改评估/校准逻辑, 不改训练
  风险: 低, 不影响分类

────────────────────────
方向B (高风险): 重新设计Flow架构 — 如果仍想用flow做OSR
────────────────────────

  思路: 当前4-layer ConditionalNSF条件信号太弱, 需要根本性增强

  改进点:
    a) 类专属Flow: 每个类一个独立flow (非条件共享)
       → 每个类有独立的密度模型 p(x|c)
       → OSR判据: max_c log p(x|c) < τ → unknown

    b) 更强的条件注入: FiLM层 或 cross-attention
       → 当前: condition拼接 → 改为: condition调制hidden层
       → 让条件信号真正控制flow的变换行为

    c) 更深的flow: 4层 → 8-12层
       → 更大的hidden: 128 → 256-512
       → 参数量增加4-8x, 但flow能力大幅提升

  代码改动: 重写ConditionalNSF或新建ClassSpecificFlow
  风险: 高, 可能导致过拟合 (每类flow参数多但few-shot样本少)
  不推荐: 在当前few-shot设定下 (每类5样本), 类专属flow容易过拟合
