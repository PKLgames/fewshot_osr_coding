● 可行性分析：流模型 → Few-shot 开放集识别

  已读完全部相关代码。你已有两套Few-shot方案实现（方案A+C、方案B），但缺少关键
  的训练流程设计。以下是完整分析。

  ---
  1. 数学基础：为什么流模型天然适配 Few-shot OSR

  流模型核心公式: log p(x|c) = log p_prior(z) + log|det(∂f/∂x)|
                                           ↑ 标准正态     ↑ 可精确计算

  ┌──────────────────┬────────────────────────────────────────────────────┐
  │ OSR/Few-shot需求 │                   流模型如何满足                   │
  ├──────────────────┼────────────────────────────────────────────────────┤
  │ 已知类分类       │ argmax_c p(x|prototype_c) — 比较各类条件密度       │
  ├──────────────────┼────────────────────────────────────────────────────┤
  │ 未知类检测       │ max_c p(x|prototype_c) < τ — 似然阈值判断          │
  ├──────────────────┼────────────────────────────────────────────────────┤
  │ Few-shot适应     │ 用K个样本计算 prototype = mean(z_i) — 无需重训练流 │
  └──────────────────┴────────────────────────────────────────────────────┘

  流模型是唯一能精确计算密度的生成模型（VAE只能近似，GAN无法计算），这对OSR至
  关重要。

  ---
  2. 你已有方案对比分析

  方案A — 隐空间原型匹配 (FewShot_FlowAC.py:PrototypeClassifierExpert)

  x → cINN(无条件) → z → ||z - μ_c||² / σ² → 分类分数

  问题：
  - condition_dim=0，流学习的是全局映射，不是类条件映射
  - 本质退化为"用cINN学一个度量空间"，和Prototypical Network无本质区别
  - _forward_density() 混合了 flow log_prob + 马氏距离，两个信号可能冲突
  - 失去了流模型最核心的优势：精确密度估计

  方案B — 条件流原型分类 (FewShot_FlowB.py:ConditionalFlowExpert)

  x → cINN(condition=prototype_c) → log p(x|prototype_c)  ← 精确条件密度

  问题：
  - 架构最合理：直接用原型向量作为cINN条件输入
  - 但训练时用可学习原型，推理时换成support-set计算的原型
  - cINN没见过"动态计算的原型"，分布偏移可能导致性能崩塌
  - 推理开销大：每个query需N_c次cINN前向传播

  两者共同缺失

  ┌────────────────┬───────────────────────────────────────────┐
  │    缺失环节    │                   后果                    │
  ├────────────────┼───────────────────────────────────────────┤
  │ 无Episodic训练 │ 流没学过从support-set动态构建原型，泛化差 │
  ├────────────────┼───────────────────────────────────────────┤
  │ 无元学习目标   │ 优化的是固定类的NLL，不是few-shot准确率   │
  ├────────────────┼───────────────────────────────────────────┤
  │ 无OSR阈值校准  │ 未知类检测的阈值是拍脑袋的，没有校准流程  │
  └────────────────┴───────────────────────────────────────────┘

  ---
  3. 核心结论：方案B + Episodic元训练 = 最优路线

  方案B的架构是正确的，但需要配套的训练流程。方案A退化为度量学习，失去了流模型
  优势。

  阶段2：cINN Episodic 元训练（关键创新）

  class EpisodicTrainer:
      """
      Episodic meta-training for cINN
   
      每个 Episode:
        1. 从 base classes 中随机采样 N 个类
        2. 每类采样 K 个 support + Q 个 query
        3. 用 support 计算原型 → 作为 cINN 条件
        4. 在 query 上计算损失 → 反传更新 cINN
   
      关键: cINN 学会处理 "任意原型向量" 作为条件,
            而非固定的可学习原型 → 泛化到新类
      """

      def __init__(self, feature_extractor, flow_model,
                   N_way=5, K_shot=5, Q_query=15):
          # 冻结特征提取器
          for p in feature_extractor.parameters():
              p.requires_grad = False
          self.feature_extractor = feature_extractor
          self.flow = flow_model          # ConditionalFlowExpert
          self.N = N_way
          self.K = K_shot
          self.Q = Q_query

      def sample_episode(self, dataset, num_base_classes):
          """采样一个 episode"""
          # 1. 随机选 N 个类
          classes = random.sample(range(num_base_classes), self.N)

          support_feats, support_labels = [], []
          query_feats, query_labels = [], []

          for new_label, c in enumerate(classes):
              # 2. 每类采 K+Q 个样本
              samples = dataset.get_class_samples(c, self.K + self.Q)
              feats = self.feature_extractor(samples)  # (K+Q, 32)

              support_feats.append(feats[:self.K])
              support_labels.extend([new_label] * self.K)
              query_feats.append(feats[self.K:])
              query_labels.extend([new_label] * self.Q)

          support_feats = torch.cat(support_feats)    # (N*K, 32)
          support_labels = torch.tensor(support_labels)
          query_feats = torch.cat(query_feats)        # (N*Q, 32)
          query_labels = torch.tensor(query_labels)

          return support_feats, support_labels, query_feats, query_labels

      def compute_prototypes(self, support_feats, support_labels):
          """从 support set 计算各类原型"""
          prototypes = []
          for c in range(self.N):
              mask = support_labels == c
              prototypes.append(support_feats[mask].mean(dim=0))
          return torch.stack(prototypes)  # (N, 32)

      def episode_loss(self, support_feats, support_labels,
                       query_feats, query_labels):
          """单个 episode 的损失"""
          prototypes = self.compute_prototypes(
              support_feats, support_labels)  # (N, 32)

          B = query_feats.size(0)
          N = self.N

          # === 核心: 用动态原型作为 cINN 条件 ===
          log_probs = torch.zeros(B, N, device=query_feats.device)
          for c in range(N):
              condition = prototypes[c].unsqueeze(0).expand(B, -1)
              log_probs[:, c] = self.flow.flow.log_prob(
                  query_feats, condition)

          # 分类损失
          preds = F.log_softmax(log_probs, dim=1)
          loss = F.nll_loss(preds, query_labels)

          # 密度正则: 鼓励同类样本高密度，异类低密度
          # (防止流坍缩为平凡解)
          target_log_prob = log_probs.gather(
              1, query_labels.unsqueeze(1)).mean()
          loss -= 0.1 * target_log_prob  # 最大化目标类密度

          return loss, preds

      def train(self, dataset, num_base_classes,
                num_episodes=10000, lr=1e-4):
          """Episodic 训练主循环"""
          optimizer = torch.optim.Adam(
              self.flow.parameters(), lr=lr)

          for ep in range(num_episodes):
              s_feat, s_lab, q_feat, q_lab = \
                  self.sample_episode(dataset, num_base_classes)

              loss, preds = self.episode_loss(
                  s_feat, s_lab, q_feat, q_lab)

              optimizer.zero_grad()
              loss.backward()
              torch.nn.utils.clip_grad_norm_(
                  self.flow.parameters(), 1.0)
              optimizer.step()

              if ep % 100 == 0:
                  acc = (preds.argmax(1) == q_lab).float().mean()
                  print(f"Episode {ep}: loss={loss:.4f}, "
                        f"acc={acc:.2%}")

  阶段3：OSR 似然阈值校准

  def calibrate_osr_threshold(flow_model, feature_extractor,
                              known_dataset, holdout_dataset,
                              target_fpr=0.05):
      """
      用 holdout 类模拟未知类, 校准似然阈值 τ
   
      思路:
        对已知类样本: max_c log p(x|proto_c) 应该 > τ
        对未知类样本: max_c log p(x|proto_c) 应该 < τ
        τ 选择使得 FPR (已知类被误判为未知的比例) ≈ target_fpr
      """
      known_scores = []   # 已知类的最高似然分数
      unknown_scores = [] # 未知类的最高似然分数

      with torch.no_grad():
          # 已知类分数
          for batch in known_dataset:
              feats = feature_extractor(batch)
              prototypes = ...  # 已知类的原型
              max_score = compute_max_log_prob(
                  feats, prototypes, flow_model)
              known_scores.append(max_score)

          # 未知类分数 (用 holdout 类模拟)
          for batch in holdout_dataset:
              feats = feature_extractor(batch)
              max_score = compute_max_log_prob(
                  feats, prototypes, flow_model)
              unknown_scores.append(max_score)

      known_scores = torch.cat(known_scores)
      unknown_scores = torch.cat(unknown_scores)

      # 找到满足 FPR 的阈值
      sorted_known, _ = known_scores.sort(descending=True)
      tau = sorted_known[int(len(sorted_known) * target_fpr)]

      # 评估
      tpr = (unknown_scores < tau).float().mean()  # 未知类检出率
      print(f"阈值 τ={tau:.4f}")
      print(f"未知类检出率(TPR): {tpr:.2%}")
      print(f"已知类误判率(FPR): {target_fpr:.2%}")

      return tau

  5. cINN 预训练目标函数

  当前cINN用标准NLL训练（log_prob方法）。在Few-shot场景下，预训练目标应改为：

  标准训练:  L = -log p(x|c_learnable)         ← 固定条件，优化密度
  元训练:    L = CE(query_preds, query_labels)   ← 优化分类准确率
           + λ₁ · (-log p(x_query|proto_support))  ← 密度约束
           + λ₂ · ||z||²                          ← 隐空间正则
           + λ₃ · H(prototype_weights)            ← 原型多样性

  关键差异：元训练不优化某个固定分布的NLL，而是优化"从support
  set构建原型后在query上的分类能力"。

    核心问题诊断                                                                
                                                            
  1. 迁移能力差：Base 类 90%+ vs Novel 类
  ~40%，说明模型学到的特征不具备跨类泛化能力，Flow classifier 过拟合到 base
  类的分布
  2. OSR 阈值崩溃：Known TNR=0.33%
  意味着模型把几乎所有样本都判为"未知"，Mahalanobis 距离分布中 known (-3.16)  
  和 unknown (-6.45) 分离度仅 3.29，阈值 -1.72 把几乎全部样本都划入 unknown
  3. 训练严重过拟合：15% 的 train-val gap，说明 episodic training 的正则化不够
                                                            
  下一步建议

  1. 增强 Novel 类泛化：
    - 在 episode 中引入 novel class 的模拟（如用 base class
  的线性组合/扰动模拟 unknown）
    - 增加 proto noise std（当前 0.05 太保守）
    - 考虑加入 auxiliary loss 促进特征空间的类间分离
  2. 改进 OSR 判决机制：
    - 当前 Mahalanobis 阈值方法在 flow latent space 中分离度不够，考虑换用
  energy-based 或 OpenMax 方法                                                
    - 或在 flow 输出的 log-likelihood 上直接做阈值判断
  3. 缓解过拟合：

    - 增加 dropout / weight decay
    - 减少 episode 数量或加强 data augmentation

      num_iters=3, confidence_threshold=0.8)

  突破点6: 减少feature augmentation强度

  训练时的augmentation过于激进 (episodic_trainer.py:1604-1612):
  scale = 0.75 + 0.50 * torch.rand_like(query_feats)  # ±25%缩放
  mask = (torch.rand_like(query_feats) > 0.12).float()  # 12%特征mask
  query_feats = query_feats + 0.03 * torch.randn_like(query_feats)  # 噪声    
  
  加上prototype噪声 (proto_noise_std=0.2) 和support mixup,                    
  总共4层augmentation。建议减少到2层, 或降低强度。
