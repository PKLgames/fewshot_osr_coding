## III. Method

### A. Problem Formulation

The FOAC task is defined over three disjoint label sets. **Base classes** \(\mathcal{D}_{\text{base}}\) contain hundreds of labeled examples per class for training the feature extractor and OSR heads; they are never encountered at evaluation. **Novel classes** \(\mathcal{D}_{\text{novel}}\) are the categories the model must learn from sparse support, partitioned into episodes each with N classes, K support examples, and Q query examples per class. **Unknown classes** form a third pool disjoint from both \(\mathcal{D}_{\text{base}}\) and \(\mathcal{D}_{\text{novel}}\), appearing only at test time for rejection.

A single evaluation episode is defined by a support set \(\mathcal{S} = \{(\mathbf{x}_{i}, y_{i})\}_{i=1}^{N \times K}\) and a query set \(\mathcal{Q} = \{(\mathbf{x}_{j}, y_{j})\}_{j=1}^{N \times Q} \;\cup\; \{(\mathbf{x}_{k})\}_{k=1}^{M}\), where the trailing M queries are unlabeled unknowns drawn uniformly from the unknown-class pool, intermixed with known queries in random order.

The model maps each query through a shared feature extractor to an embedding \(\mathbf{h}\), then routes it through two parallel heads. A **classification head** produces a distribution \(\hat{\mathbf{y}} \in \Delta^{N}\) over known classes via prototype-based softmax [1]. An **OSR detection head** outputs a scalar \(s_{\text{osr}} \in \mathbb{R}\) (higher = more likely known). The rejection rule is:

\[
\text{decision} = \begin{cases}
\text{reject (unknown)} & \text{if } s_{\text{osr}} < \tau, \\
\arg\max_{c} \hat{y}_{c} & \text{otherwise},
\end{cases}
\]

with threshold \(\tau\) calibrated to achieve TNR = 95% on a held-out split of the support set, disjoint from both the prototype samples and evaluation queries [5], [8]. This avoids the self-calibration loop that renders TNR artificially constant.

Performance is measured along two axes. Closed-set: classification accuracy (ACC) and macro-AUROC (one-vs-rest) over known queries that survive rejection. Open-set: AUROC [14], OSR Score = (TPR + TNR) / 2 at TNR = 95%, and TPR@TNR95.

### B. Episodic Training Framework

Training follows the episodic protocol [1], [2]. Each episode matches the FOAC test structure: N classes drawn from \(\mathcal{D}_{\text{base}}\), K support and Q query samples per class, with M unknown queries injected from a disjoint base subset. Training uses only \(\mathcal{D}_{\text{base}}\); novel-class data never appears, ensuring evaluation measures generalization to genuinely unseen categories.

An optional Flow Transform [17], [18] (dashed box, ~25K parameters) warps \(\mathbf{z}\) to \(\mathbf{h}\) via four affine coupling layers. Input audio is converted to 64-band log-mel spectrograms (96 frames, 0.96 s) and encoded by frozen YAMNet [11] pretrained on AudioSet [10]. Backbone fine-tuning produced no consistent gain on TAU22 and mild degradation on TAU19.

An optional **Flow Transform** stacks four affine coupling layers [17], [18] mapping \(\mathbf{z} \in \mathbb{R}^{1024}\) to \(\mathbf{h} = f_{\phi}(\mathbf{z})\), where \(f_{\phi}\) is invertible with tractable log-determinant Jacobian. The flow adds ~25K parameters and aims to Gaussianize per-class distributions, sharpening covariance estimates for distance-based detectors. Its benefit is dataset-dependent (§IV.F).

The embedding \(\mathbf{h}\)—or \(\mathbf{z}\) directly when the flow is removed—feeds two parallel branches (see Fig 1). The **classification branch** computes N class prototypes via support-set averaging and produces query class scores through a softmax over Euclidean distances to those prototypes [1]. The **OSR branch** routes the same embedding through the active detection head (Section III.C, expanded in the Fig 1 inset) to produce \(s_{\text{osr}}\). Both branches share the same feature representation; there is no separate OSR-specific feature extractor.

### C. Six OSR Detection Heads

The six heads span distinct operating principles and are shown together in the OSR branch inset of Fig 1. Each head receives the feature representation \(\mathbf{h}\) (post-flow, if the flow is active) and outputs a scalar \(s_{\text{osr}}\); heads that require per-class modeling obtain the support set's class assignments to construct their internal representations.

**1. Anti-Prototype Head (anti_proto).** Following [9], this head learns an anti-prototype \(\mathbf{a} \in \mathbb{R}^{d}\) as a negative center for all known classes. Given N class prototypes \(\{\mathbf{p}_{c}\}_{c=1}^{N}\) (mean of K support embeddings), the open-set score is:

\[
s_{\text{anti}} = d(\mathbf{h}, \mathbf{a}) - \min_{c \in \{1,\ldots,N\}} d(\mathbf{h}, \mathbf{p}_{c})
\]

where \(d(\cdot, \cdot)\) is Euclidean distance. A positive score indicates the query is closer to a known prototype than to \(\mathbf{a}\). The anti-prototype is trained via the reciprocal loss (§III.D).

**2. Mahalanobis Distance Head (mahal).** Per-class Gaussian \(\mathcal{N}(\boldsymbol{\mu}_{c}, \mathbf{\Sigma}_{c})\) is fit to support embeddings [8], with shrinkage toward a pooled diagonal for stability at small K: \(\mathbf{\Sigma}_{c} = (1 - \lambda) \mathbf{S}_{c} + \lambda \mathbf{\Sigma}_{\text{pooled}}\) (\(\lambda = 0.5\)). The score is negative Mahalanobis distance to the nearest class:

\[
s_{\text{mahal}} = -\min_{c} \sqrt{(\mathbf{h} - \boldsymbol{\mu}_{c})^{T} \mathbf{\Sigma}_{c}^{-1} (\mathbf{h} - \boldsymbol{\mu}_{c})}.
\]

This head has no learned parameters and serves as the `only_distance_head` baseline.

**3. OOD Head OSR23 (osr23).** A GMM with \(G = 4\) components is fit per episode to the aggregated support features of all N known classes via EM initialized from k-means [24]. The score is log-likelihood under the mixture:

\[
s_{\text{osr23}} = \log \sum_{g=1}^{G} \pi_{g} \, \mathcal{N}(\mathbf{h}; \boldsymbol{\mu}_{g}, \mathbf{\Sigma}_{g})
\]

where \(\pi_{g}\) are mixing coefficients. Unknowns are expected in low-density regions.

**4. OOD Head Extended V2 (ext_v2).** Augments the Mahalanobis detector with a learned linear projection \(\mathbf{W} \in \mathbb{R}^{d \times d'}\) to a discriminative subspace [8]:

\[
s_{\text{ext}} = -\min_{c} \sqrt{(\mathbf{W}\mathbf{h} - \tilde{\boldsymbol{\mu}}_{c})^{T} \tilde{\mathbf{\Sigma}}_{c}^{-1} (\mathbf{W}\mathbf{h} - \tilde{\boldsymbol{\mu}}_{c})}
\]

where \(\tilde{\boldsymbol{\mu}}_{c} = \mathbf{W}\boldsymbol{\mu}_{c}\) and \(\tilde{\mathbf{\Sigma}}_{c}\) is the projected-space covariance. \(\mathbf{W}\) is trained end-to-end via the OSR loss (~300 added parameters).

**5. OOD Head Cluster V2 (clust_v2).** Per-class density estimation treating all K support embeddings as cluster centers [24]; the score is the negative distance to the nearest center:

\[
s_{\text{clust}} = -\min_{c \in \{1,\ldots,N\}} \min_{k \in \{1,\ldots,K\}} \|\mathbf{h} - \mathbf{h}_{c,k}\|_{2}.
\]

When K = 1 this reduces to nearest-neighbor distance. For K > 1, retaining individual support samples is advantageous when outliers would distort a mean prototype.

**6. OOD Head Fusion V2 (fusion_v2) — Core Contribution.** The fusion head (see Fig 1, bottom right of OSR inset) combines ext_v2 and clust_v2 through a learned scalar weight \(\alpha \in [0, 1]\):

\[
s_{\text{fusion}} = \alpha \cdot s_{\text{ext}} + (1 - \alpha) \cdot s_{\text{clust}}.
\]

The two heads capture complementary failure modes: ext_v2 learns a discriminative boundary (accurate when test unknowns resemble training, brittle otherwise); clust_v2 provides a generative density estimate (less sensitive to distribution shift but noisier at small K). Blending lets the model favor the more reliable signal per domain and shot count. \(\alpha\) is optimized jointly with the multi-objective loss (§III.D). \(s_{\text{fusion}}\) substitutes for \(s_{\text{osr}}\) at inference (§III.A).

### D. Training Objectives

The total loss combines four terms:

\[
\mathcal{L} = \mathcal{L}_{\text{cls}} + \lambda_{\text{osr}} \mathcal{L}_{\text{osr}} + \lambda_{\text{rec}} \mathcal{L}_{\text{rec}} + \lambda_{\text{sep}} \mathcal{L}_{\text{sep}}.
\]

**Classification loss** \(\mathcal{L}_{\text{cls}}\) is cross-entropy over the N known classes on both support and query samples, encouraging well-separated class embeddings and correct prototype-based predictions.

**OSR loss** \(\mathcal{L}_{\text{osr}}\) is binary cross-entropy on the open-set scores [5], [6]: known queries = 1 (accept), unknown = 0 (reject). This is the primary training signal for heads with learnable parameters (ext_v2, fusion_v2).

**Reciprocal loss** \(\mathcal{L}_{\text{rec}}\) implements the constraint from [9] with \(\lambda_{\text{rec}} = 0.3\), pushing the anti-prototype \(\mathbf{a}\) away from all known-class embeddings while regularizing its norm.

**Separation loss** \(\mathcal{L}_{\text{sep}}\) encourages known/unknown feature separation via a contrastive term (\(\lambda_{\text{sep}} = 0.02\)) [24]. Global gradient clipping stabilizes early training when prototypes are poorly initialized.

**TABLE 1.** Model configuration variants for ablation experiments. All variants share the YAMNet backbone [11], the episodic sampling protocol, and optimizer settings (AdamW, lr = \(2 \times 10^{-4}\), 200 warmup steps, 3000 training episodes).

To isolate the contribution of each architectural component, we define six configurations by selectively removing elements from the full model (TABLE 1). `full_model` includes the Flow Transform, the active OOD head, reciprocal loss, and per-episode threshold adaptation. Each variant strips one component: `wo_flow_transform` removes the normalizing flow [17], [18]; `wo_ood_head` disables the OSR-specific training loss, retaining only classification and separation loss; `wo_reciprocal` drops reciprocal attention [9]; `wo_threshold` replaces the calibrated threshold with a fixed percentile; `only_distance_head` reduces the system to the bare Mahalanobis detector [8]—no flow, no OOD-specific training, no reciprocal regularization.

All variants share the same YAMNet backbone [11], episode sampling procedure, and optimizer settings (AdamW, lr = \(2 \times 10^{-4}\), 200 warmup steps, 3000 training episodes). Cross-configuration comparisons therefore reflect genuine architectural differences rather than confounding training protocol factors.
