一、osr21核心思路: Flow原理的新角色
════════════════════════════════════════════════════════════════════

  osr18/19失败原因回顾:
    Flow密度估计 ≈ 特征空间密度 → 与Mahalanobis/anti_proto冗余
    Flow z空间 ≈ 特征空间 → 没有学到新信息
    → Flow不应被用作"另一个密度估计器"

  osr21新思路: Flow作为"特征生成器"而非"密度估计器"
    ┌─────────────────────────────────────────────────────────┐
    │ osr18/19: features → Flow → density → score (失败,冗余) │
    │                                                      │
    │ osr21:    z ~ prior → Flow⁻¹ → pseudo-OOD features    │
    │           用于增强OOD head训练 (新角色,无冲突)         │
    │                                                      │
    │ osr21:    features → Flow(可学习变换) → transformed    │
    │           在变换后空间做anti_prototype (非线性边界)     │
    └─────────────────────────────────────────────────────────┘

  为什么这次不同:
    1. Flow不参与评分 → 不与anti_proto/ood_head_ext冗余
    2. Flow生成训练数据 → 间接提升OOD head质量
    3. Flow变换特征空间 → 捕获非线性边界, 补充anti_proto的线性反射

二、osr21a: Flow条件生成器 — 改进伪OOD样本质量
════════════════════════════════════════════════════════════════════

  ★ 目标: 提升ood_head_extended的TPR (当前16.33%, 目标20%+)

  ── 问题分析 ──
    当前伪OOD生成 (CurriculumOODSampler):
      Level 1: mixup + 高斯噪声 → 太简单, OOD head过拟合
      Level 2: GMM低密度采样 → GMM假设高斯, 边界不精确
      Level 3: 对抗样本(高熵) → 依赖当前分类器质量, bootstrap循环

    GMM的核心限制:
      - 假设每个类是高斯分布 → 真实特征分布是非高斯的
      - 低密度区域采样可能产生"不可能"的特征(脱离流形)
      - GMM生成的样本不够"真实", OOD head学到的边界泛化差

  ── 方案: 用条件Flow替代GMM做伪OOD生成 ──

    步骤1: 训练条件Flow (在Phase 1后, Phase 2前, 一次性)
      - 输入: base类特征 (按类条件)
      - Flow架构: 轻量ConditionalINN, 3 coupling layers
      - 条件: class_id (one-hot或prototype)
      - 训练目标: 最大化 p(x | class) (标准MLE)
      - 训练数据: 只用base类特征, 无泄露

    步骤2: 生成伪OOD样本 (每episode动态)
      策略A — 类间插值:
        z1, z2 ~ N(0,I)  (两个不同prior样本)
        z_interp = α·z1 + (1-α)·z2  (在z空间插值)
        x_interp = Flow⁻¹(z_interp | class_c)  (逆变换到特征空间)
        → 生成"在类间游走"的样本, 更像真实unknown

      策略B — 低密度区域采样:
        z ~ N(0,I), 但|z|较大(远离原点)
        x = Flow⁻¹(z | class_c)
        → Flow学到的密度 p(x|c) ∝ exp(-|z|²/2)
        → |z|大的样本在特征空间是低密度的, 更接近边界

      策略C — 类条件不匹配:
        z ~ N(0,I)
        x = Flow⁻¹(z | class_c1)  但标记为 "不属于c2"
        → 生成对c1合法但对c2非法的样本 → 精确的类间边界

    步骤3: 替换CurriculumOODSampler的Level 2
      - 保留Level 1 (mixup) 作为warmup
      - Level 2: 从GMM边界采样 → Flow条件生成
      - 保留Level 3 (对抗样本) 不变

  ── 代码修改点 (episodic_trainer.py) ──

    1. 新增类 FlowOODGenerator (在CurriculumOODSampler之后):
       ```python

               ...

               # 策略B: 远离原点的z → 特征空间低密度样本
       ```

    2. 修改CurriculumOODSampler:
       - __init__: 新增FlowOODGenerator选项
       - _sample_level2: 从FlowOODGenerator生成, 替代GMM

  ── 预期效果 ──
    ood_head_extended TPR: 16.33% → 18-20%
    → ensemble_anti_oodext: 22.91% → 24-26%
    原因: 更真实的伪OOD → OOD head学到更精确的边界 → 更好的泛化

  ── 风险 ──
    - Flow在小数据(每类~200样本, 64维)上可能过拟合 → 需正则化
    - 生成样本质量取决于Flow训练质量 → 需监控生成样本分布
    - 训练时间增加(一次性, ~2-5分钟)

三、osr21b: Flow特征变换器 — 非线性边界增强anti_prototype
════════════════════════════════════════════════════════════════════

  ★ 目标: 提升anti_prototype的TPR (当前18.92%, 目标22%+)

  ── 问题分析 ──
    anti_prototype的核心: 特征 → L2距离 → 原型反射 → 线性判别
    限制: 假设类间边界是超平面 → 真实边界可能是非线性的(特别是声景特征)
    osr20已验证: 余弦距离/方差归一化不如L2 → 问题不在度量, 在空间结构

  ── 方案: 用可学习Flow变换特征空间 ──

    核心思路:
      原始空间: anti(x) = 2·center - proto, score = -d(x,proto) + d(x,anti)
      变换后: anti'(x) = 2·center' - proto', score = -d(f(x),f(proto)) + d(f(x),f(anti))
      其中f是可学习的Flow(双射) → 变换后空间可能有更线性的边界

    步骤1: 添加Flow变换层到EpisodicFlowClassifier
      - 在feature_adapter之后, distance_head之前
      - Flow是permutation + coupling layers → 可逆, 不丢信息
      - 训练目标: 在episodic training中端到端优化

    步骤2: 训练
      - Flow与现有分类器一起训练
      - 分类loss → 拉开同类/异类距离 → Flow学到使边界更线性
      - anti_prototype在变换后空间自动获得非线性边界

    步骤3: 评估
      - 在变换后特征上做anti_prototype
      - 原始特征和变换特征可ensemble → 捕获线性和非线性边界

  ── 代码修改点 (episodic_trainer.py) ──

    1. 修改EpisodicFlowClassifier:
       ```python
       class EpisodicFlowClassifier(nn.Module):
           def __init__(self, input_dim=64, ...):
               ...
               # osr21b: 可学习特征变换Flow
               self.feature_transform = LightweightFlowTransform(
                   input_dim=input_dim,
                   n_coupling_layers=2,  # 轻量, 避免过拟合
                   hidden_dim=input_dim // 2)

           def classify(self, features, prototypes):

               features, prototypes = self.adapt_features(features, prototypes)

                   prototypes = self.feature_transform(prototypes)

               dist_feats = self.distance_head(features)
               dist_protos = self.distance_head(prototypes)
               ...
       ```

    2. 新增LightweightFlowTransform:

    3. 评估时新增方法:
       - score_anti_prototype_flow: 在Flow变换后空间做anti_proto
       - ensemble_anti_flow_oodext: anti_flow + ood_head_ext 融合

  ── 预期效果 ──
    anti_prototype TPR: 18.92% → 20-22%
    → ensemble: 22.91% → 24-26%
    原因: 非线性变换 → 更好的类间分离 → anti_proto反射更准确

  ── 风险 ──
    - Flow可能学到identity (osr19的教训) → 需加regularization
    - 增加训练复杂度 → 需careful LR tuning
    - 中等风险, 需osr21a先验证Flow生成器有效

四、osr21c: Flow Jacobian局部曲率 — 第三种独立OSR信号
════════════════════════════════════════════════════════════════════

  ★ 目标: 提供ensemble的第三种信号 (目标TPR 25%+)

  ── 问题分析 ──
    osr20b ensemble = anti_proto(几何) + ood_head_ext(统计)
    如果有第三种独立信号 → 三路融合 → 更鲁棒

  ── 方案: Flow Jacobian的局部体积变化 ──

    核心原理:
      Flow f: x → z 是双射, Jacobian J(x) = ∂z/∂x
      log det J(x) = 局部体积变化率
      - |log det J| 大 → Flow在该点"大幅拉伸/压缩"空间
      - 已知类中心附近: Flow已学好 → log det J 接近某稳定值
      - 未知区域: Flow外推 → log det J 异常(偏大或偏小)

    与anti_proto的互补:
      anti_proto: "这个点到最近原型的距离" (全局几何)
      log det J:  "Flow在这个点附近如何变形空间" (局部几何)
      → 不同视角, 可互补

    与ood_head_ext的互补:
      ood_head_ext: 11个手工统计特征 (全局)
      log det J: 单个标量, 但反映模型对局部结构的"不确定性"
      → log det J可作为ood_head_ext的第12个特征

  ── 代码修改点 (episodic_trainer.py) ──

    1. 在OSRCalibrator中新增:
       ```python
       def score_flow_jacobian(self, features, prototypes, batch_size=4096):
           """osr21c: 用Flow Jacobian的log det作为OSR评分"""
           self.flow.eval()
           all_scores = []
           with torch.no_grad():
               for i in range(0, len(features), batch_size):
                   batch = features[i:i+batch_size].to(self.device)
                   # Forward pass with log_det
                   z, log_det = self.flow.feature_transform.forward_with_logdet(batch)
                   all_scores.append(log_det.cpu())
           return torch.cat(all_scores)
       ```

    2. 三路ensemble:
       ```python

           """osr21c: anti_proto + ood_head_ext + flow_jacobian 三路融合"""
           # 搜索三维权重: alpha, beta, gamma (alpha+beta+gamma=1)
           ...
       ```

  ── 预期效果 ──
    三路ensemble TPR: 22.91% → 25%+
    但: 高度依赖osr21b的Flow变换是否学到有意义的空间结构

  ── 风险 ──
    - osr19教训: Flow可能学identity → log det ≈ 0 → 无信号
    - 需osr21b先验证Flow学到有意义的变换
    - 高风险高回报

七、关键设计原则
════════════════════════════════════════════════════════════════════

    1. Flow不参与评分 → 不与现有OSR方法冲突
       osr18/19失败 = Flow密度与特征统计量冗余
       osr21 Flow = 生成器/变换器, 间接提升现有方法

    2. 轻量化 → 避免过拟合
       64维特征, 每类~200样本 → Flow必须轻量
       2-3 coupling layers, hidden_dim ≤ input_dim

    3. 与现有架构兼容 → 不破坏已验证的osr20流程
       osr21a: 只替换CurriculumOODSampler的Level 2
       osr21b: 在feature_adapter后添加可选Flow层
       osr21c: 在评估阶段添加log_det特征

    4. 防止Flow学identity → osr19的核心教训
       osr21a: Flow用于生成, 训练loss = MLE on known features
               即使Flow学identity, 生成的z空间插值仍有意义
       osr21b: 添加正则化:
               - log_det正则: 鼓励|log det J| > ε (非平凡变换)
               - 分类loss驱动: 变换后分类loss下降 → 有用
       osr21c: 依赖osr21b的Flow, 仅在osr21b有效时启用
