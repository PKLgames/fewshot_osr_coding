================================================================================
十、FOAC-AIFP OSR 评估 TNR 硬编码修复方案 (2026-05-11)
================================================================================

  问题: FOAC-AIFP 消融实验所有 72 个数据点 TNR 恒为 95.556%, 原因是
        eval_fsl_nplus1() 用测试集自身校准阈值再测 TNR, 形成自循环。

  根因定位 (trainers/trainer.py):
    L355-371  eval_fsl_nplus1():
      sorted_known = np.sort(known_scores)                    # 测试集已知类分数排序
      idx95 = min(int(len(sorted_known) * 0.05), ...)         # 取第5百分位
      threshold_95 = sorted_known[idx95]                      # 阈值 = 测试集自身分位数
      tnr = float(np.mean(known_scores >= threshold_95))      # TNR 永远 ≈ 95.556%
      → 阈值从测试集自身而来, TNR 变成纯数学结果 (1 - int(N*0.05)/N), 与模型无关
      → N=45 时 TNR=43/45=95.556%, 所有配置/checkpoint 完全一致

    L556-567  compute_tpr_at_tnr(): 同样逻辑, 用于 run_osr_eval()
      但 run_osr_eval 的已知类样本量大(N=数千), 所以 95%分位 ≈ 95.0%(基本准确)

  对比 Episodic Trainer 的正确做法:
    - 校准集 (calib.csv) → 拟合 threshold (TNR=95%)
    - 测试集 (evaluate.csv) → 应用 threshold, 测量真实 TNR
    - TNR 会有自然波动 (因为校准集 ≠ 测试集, 真实分布有差异)

  ── 修复方案 ──

  方案 A: 修复 eval_fsl_nplus1 — 支持集校准 (最小改动, 推荐)
  ────────────────────────────────────────────
  原理: 每个 episode 有 support/query/open 三组数据。
        用 support set 的已知类分数校准阈值, 用 query set 测量 TNR。
  步骤:
    1. compute_feats() 额外返回 support set 的 softmax 分数
       → 需要 net() 前向时额外输出 support_data 的分类概率
    2. eval_fsl_nplus1() 接收 support_scores, query_scores, open_scores
    3. 在 support_scores 上取第5百分位作为 threshold
    4. 在 query_scores 上测量 TNR (会自然偏离 95%)
  改动文件:
    - trainers/trainer.py: compute_feats() 返回 support probs
    - trainers/trainer.py: eval_fsl_nplus1() 签名 + 逻辑
    - trainers/trainer.py: run_test_fsl() 传参适配
  优点: 最小改动(~20行), 不破坏现有 per-episode 评估协议
  缺点: support set 样本少 (6类×5shot=30), 阈值估计噪声大

  方案 B: 扩展 run_osr_eval 覆盖全部6种 OSR 方法 (推荐作为补充)
  ────────────────────────────────────────────
  原理: run_osr_eval 已有正确的 calib/test 分离 (L570-686),
        但仅支持 2 种 OSR 方法 (anti_prototype, mahalanobis)。
        扩展为 6 种方法, 消融脚本从此函数获取 OSR 指标。
  步骤:
    1. 扩展 run_osr_eval 支持全部 6 种 OSR 方法:
       anti_prototype, feature_mahalanobis, ood_head_osr23,
       ood_head_extended_v2, ood_head_cluster_v2, ood_head_fusion_v2
    2. OOD head 类方法需要:
       a) 在 calib set 上拟合 GMM (osr23) + 训练逻辑回归权重 (osr24b)
       b) 在 test set 上推理 OOD score
       c) per-round recalibration 测 TPR@TNR95
    3. 修改 foac_exp_ablation.py run_single_ablation():
       训练完成后调用 run_osr_eval() 获取 OSR 指标,
       替代 eval_fsl_nplus1 的 tnr/tpr/osr_score
    4. AUROC 保留 eval_fsl_nplus1 的结果 (其 AUROC 计算无 self-calibration 问题)
  改动文件:
    - trainers/trainer.py: run_osr_eval() 扩展 2→6 方法
    - foac_exp_ablation.py: run_single_ablation() 调用 run_osr_eval
    - 可能需要从 episodic_trainer 移植 GMM+logreg 训练代码
  优点: 与 Episodic Trainer 评估协议完全一致 (calib/test 分离)
  缺点: OOD head 方法需训练 osr24b 逻辑回归头, 增加复杂度
  工作量: ~80行

  方案 C: eval_fsl_nplus1 内做 calib/eval 随机分半 (折中, 最快)
  ────────────────────────────────────────────
  原理: 将 query set 的已知类样本随机分成 calib(50%) + eval(50%),
        在 calib 上校准阈值, 在 eval 上测量 TNR。
        重复 10 轮随机分割, 取均值。
  步骤:
    1. 修改 eval_fsl_nplus1, 新增 num_rounds=10 参数
    2. 每轮随机打乱 known_scores, 前一半校准阈值, 后一半测量 TNR/TPR
    3. 返回 10 轮 TNR/TPR/OSR 的均值 ± 标准差
  改动文件:
    - trainers/trainer.py: eval_fsl_nplus1() (~15行)
  优点: 不需要 support set 改造, 不需要 run_osr_eval, 最快实现
  缺点: 样本量减半, query 已知类数量本就不多 (6类×Q=~45个), 方差增大
  工作量: ~15行
